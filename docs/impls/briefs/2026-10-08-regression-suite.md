## Deliverables

1. **`docs/tests/regression/README.md`.** What the suite is and is not (live checks only; CI tests stay in the crates), the folder layout, the case ID scheme (`AREA-FEATURE-NN`, never reused, retired cases marked rather than renumbered), the columns, the tiers, how a run is recorded, and the promotion rule below. Add a short "Not carried over" table: each archive record or check left out, with the reason (retired behavior, covered by a CI test named there, or one-off investigation).
2. **One file per area**, sections per feature, one table row per case. Suggested areas, adjusted to what the records actually cover: `runtimes.md` (per-runtime lifecycle: fresh chat, second turn, overrides, tool activity, interrupt, recovery, stop/resume, new conversation and its resume, mission startup in a fresh folder, status and hooks), `terminal.md` (rendering, colors, resize, scrollback, paste, multiline, drafts, IME), `workspace.md` (windows, tabs, panes, splits, live cwd, sidebar, keyboard creation), `missions.md` (crews, mission start, messaging and inbox delivery, asks, watch and feed), `daemon.md` (`runnerd` lifecycle: Keep and Stop on quit, reconnect, crash and restart notices, resume), `settings.md` (agents and updates, MCP, skills, install), `cli.md`. Columns: `ID`, `Case` (the action, in a sentence or two), `Expected` (observable behavior), `Platform` (`mac`, `win` or `both`), `Needs` (empty, or any of `account` for a real agent account, `computer-use`, `human` for a manual step such as a divider drag, `windows-host`), `Tier` (`smoke` or `full`), `Origin` (link to the archive record, with its row ID where it had one, or the issue). Runtime cases are written once and run per runtime; say which runtimes a case applies to when not all five.
3. **Tiers.** `smoke` is the subset to run before every release: the runtime lifecycle core on each platform plus one or two cases per area, small enough for one QA session (aim for roughly 30–40 cases). `full` is everything, for major refactors. Smoke is a selection from the suite, not a second list.
4. **`full-smoke-test.md` keeps the procedure.** Setup, isolation, candidate identity, computer-use rules, cleanup and the run record stay there; its case matrix moves into `regression/runtimes.md` with nothing lost (the evidence each check requires moves with it), and the procedure points to the suite for what to run. A run is recorded as `docs/tests/runs/YYYY-MM-DD-<platform>.md`: candidate, environment, then case ID → Passed, Failed, Blocked or Skipped with evidence, and findings. Describe that format in the README; do not create a run file.
5. **The promotion rule in `AGENTS.md`.** In Post-mission cleanup step 3, when a feature's test record is archived, its lasting live checks are added to `docs/tests/regression/` (or the record names why none apply). Update the Full Smoke Tests section and `docs/README.md` to point at the suite. `AGENTS.md` and `CLAUDE.md` are one file; edit `AGENTS.md`.

Every case must trace to an archive record, a spec, an issue or current code; do not invent coverage. Write cases as observable behavior a QA agent can check in the live development app or CLI, not as implementation details. Markdown prose is one paragraph per line. Do not edit or move the archive records themselves.
