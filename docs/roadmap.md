# Runner roadmap

Snapshot as of 2026-10-08. The live sources are [GitHub milestones](https://github.com/yicheng47/runner/milestones), [open issues](https://github.com/yicheng47/runner/issues), and [published releases](https://github.com/yicheng47/runner/releases); this file mirrors them so the state of the project is readable from the repo without a browser. Issue state, milestone assignments and release-blocker labels take precedence over milestone descriptions, which can lag. Update it when an issue changes milestone, a release is cut, or a mission lands, and move the date.

## Where the project is

- **Latest release:** [0.13.1](https://github.com/yicheng47/runner/releases/tag/v0.13.1) on 2026-10-08, a bug-fix release on top of 0.13.0. `runner mission feed --follow` subscribes to `runnerd` instead of polling, after the CLI moved from MCP to `runnerd`'s client protocol ([#821](https://github.com/yicheng47/runner/issues/821), [#822](https://github.com/yicheng47/runner/pull/822)); the MCP server and `rmcp` are gone, and `mcp.sock` survives only as a placeholder that lets `runnerd` notice an older app on macOS. Codex status hooks on Windows report over a bounded local connection instead of starting a shell per report, and status recovers after a manual `/compact` ([#797](https://github.com/yicheng47/runner/issues/797), [record](./tests/archive/797-hook-status-ipc.md)). [0.13.0](https://github.com/yicheng47/runner/releases/tag/v0.13.0), on 2026-10-06, made `runnerd` own the sessions so agents keep working when the app quits or crashes ([#645](https://github.com/yicheng47/runner/issues/645)), with the Windows regression fixes from [#812](https://github.com/yicheng47/runner/pull/812) ([record](./tests/archive/2026-10-06-pc-full-regression.md)).
- **After the release:** the mission rail truncates long session handles and clamps the session key to two lines ([#782](https://github.com/yicheng47/runner/issues/782), [#828](https://github.com/yicheng47/runner/pull/828)), the first mission of the codex trio crew, whose qa slot checked the fix in the live development app. Windows agent updates no longer require stopping running sessions ([#790](https://github.com/yicheng47/runner/issues/790), [#829](https://github.com/yicheng47/runner/pull/829)). Targeted crew messaging was filed as [#826](https://github.com/yicheng47/runner/issues/826) ([spec](./features/826-targeted-messaging.md), P2) after crews of more than three agents got noisy and slow. The live regression suite landed in [`tests/regression/`](./tests/regression/README.md) ([#830](https://github.com/yicheng47/runner/pull/830)): 160 cases in seven areas, 35 of them in the smoke tier run before a release, separate from the dated records of each run. The Windows input harness [#813](https://github.com/yicheng47/runner/issues/813) was closed as not planned on 2026-10-07: the #797 Windows QA drove live agent terminals through computer use. [#832](https://github.com/yicheng47/runner/pull/832) fixed the four `runnerd` review bugs: start and stop deadlines derived from teardown, so a slow daemon is no longer reported dead after 10 seconds ([#817](https://github.com/yicheng47/runner/issues/817)); a failed connection is logged instead of stopping the daemon and every session ([#815](https://github.com/yicheng47/runner/issues/815)); a fork gets a deadline past its 120-second bound while every other request keeps 10 seconds ([#816](https://github.com/yicheng47/runner/issues/816)); and "1 session stopped" ([#819](https://github.com/yicheng47/runner/issues/819)). A disabled Fork chat in the sidebar's tab menu now gives its reason on hover instead of under the label ([#833](https://github.com/yicheng47/runner/issues/833), [#834](https://github.com/yicheng47/runner/pull/834)).
- **Next:** 0.13.2 carries the rest of `runnerd`'s follow-through: the redraw cost of a busy chat (#814, in QA after a Codex title spinner was found waking the whole window and writing the session title on every frame), the Windows Settings offset (#824), pi sessions after a pi update (#803), and the resume stamp at a Windows restart (#820). Liquid glass ([793](./features/793-liquid-glass.md)) heads 0.14 with the command palette and desktop notifications designed in it, joined on 2026-10-08 by targeted crew messaging ([826](./features/826-targeted-messaging.md)) and mission monitoring from a chat ([748](./features/748-mission-watch-delivery.md)), which share the router's delivery path, and UI performance tests ([#831](https://github.com/yicheng47/runner/issues/831)) after the glass change. Missions as containers ([562](./features/562-mission-spawn.md)) heads 0.15 with session-to-session prompts ([704](./features/704-session-send.md)) and file preview and code review ([634](./features/634-file-preview-and-review.md)), reopened on 2026-10-08. Remote machines over ssh ([#808](https://github.com/yicheng47/runner/issues/808)) heads 0.16 with the shell and agent boundary ([795](./features/795-shell-agent-boundary.md)).

## Decisions that shape the next releases

- **`runnerd` owns the state.** Since 0.13.0 (#645) a background daemon runs the database, sessions, routers and buses, and the app and the CLI are its clients. An update restarts every session and the agents resume their conversations (spec decision 13, 2026-10-06); there is no downgrade guard, because 0.13.x has to be good enough that nobody goes back. Remote machines over ssh build on it in [#808](https://github.com/yicheng47/runner/issues/808).
- **Runner is not an agent development environment, but it shows the work.** Worktree isolation ([#403](https://github.com/yicheng47/runner/issues/403)) was closed as not planned on 2026-09-22: checkouts, editing, staging and commits belong to git, the agents and the editor. The project tree with a read-only diff viewer ([#634](https://github.com/yicheng47/runner/issues/634)) was closed the same day and reopened on 2026-10-08 for 0.15, because reading an agent's changes was still the most common reason to leave Runner; it stays read-only, and its review comments go back to the agent through the crew.
- **The README is the front door.** The landing page ([#468](https://github.com/yicheng47/runner/issues/468)) was closed as not planned the same day: visitors arrive on GitHub, and the README already explains roles, crews and missions in both languages.
- **Each agent runtime is one module.** Since #777 (2026-10-03), a runtime's argv, spawn hooks, status watcher, models, usage, skills and MCP entry live under `runtimes/<name>/` behind the `RuntimeAdapter` trait, registered in one `match`; the app's per-runtime icons and labels are one table in `runtime_ui.rs`. New runtimes ([#723](https://github.com/yicheng47/runner/issues/723)) and MCP clients ([#764](https://github.com/yicheng47/runner/issues/764)) start there.
- **Session state goes through one reducer.** Since #791 (2026-10-04), every status, draft and conversation-key update for a session passes through `SessionModel::apply` under `session/state/`; runtime watchers only translate their CLI's records into events. Status fixes change the reducer or a watcher's translation, and each is pinned by a scripted scenario and its compact golden under `session/fixtures/`.
- **OpenCode is no longer scheduled.** [#592](https://github.com/yicheng47/runner/issues/592) was closed as not planned on 2026-09-28; it is not shipped runtime support. New runtimes follow the [integration checklist](./arch/runtime-integration.md), with platform verification recorded separately from CI.
- **One `runner` binary, two modes.** Inside a mission the commands are unchanged and `--mission` defaults to the caller's own; outside, `--mission` is a flag. No second control binary, and no scoping by packaging: a mission agent's shell runs anything on `PATH`. A limit, if ever wanted, is an authorization check on `runnerd`'s side of its socket.
- **A caller is the person at the app or a roster handle, never a location.** `human` on the bus means only the person at the app UI. Inside a mission the handle comes from `RUNNER_HANDLE`; outside, `--as <handle>` names a seat the caller holds, and no handle means the person at a terminal. An outside agent that drives a mission takes a seat first. The socket's post and signal tools carry a `from` handle validated against the roster. Seats without a Runner-spawned session are #562's.
- **Runner's MCP integration was removed for 0.11.0, the release that ships the CLI.** Two ways in at once would have been confusing. The `runner-mcp` bridge, the registrations Runner wrote, and the pinned row in Settings → MCP are gone; the socket stayed as the CLI's implementation-detail transport until #821 (2026-10-07) moved the CLI onto `runnerd`'s client protocol and removed Runner's MCP server; Settings → MCP remains the catalog of the user's own servers.
- **#648 and #562 stay separate.** 648 is a surface over tools that exist and shipped in 0.11.0; 562 changes the mission model and is scheduled for 0.15. 648 reserves the coordinator verbs (`spawn`, `ps`, `wait`, `stop`, `done`); a `peek` at a worker's terminal is not supported, messages are the contract, and #562 owns the seats and the verbs.
- **pi MCP management is proposed, not shipped.** [#764](https://github.com/yicheng47/runner/issues/764) tracks adding pi to the user's MCP server catalog in 0.16. Runner currently writes no pi MCP entry and has no pi column in Settings → MCP; the Skills pane lists pi's two personal roots read-only. Mission coordination continues through the bundled `runner` CLI. The new spec's proposal to register Runner needs reconciling with the shipped MCP removal before implementation.
