# Runner roadmap

Snapshot as of 2026-10-04. The live sources are [GitHub milestones](https://github.com/yicheng47/runner/milestones), [open issues](https://github.com/yicheng47/runner/issues), and [published releases](https://github.com/yicheng47/runner/releases); this file mirrors them so the state of the project is readable from the repo without a browser. Issue state, milestone assignments and release-blocker labels take precedence over milestone descriptions, which can lag. Update it when an issue changes milestone, a release is cut, or a mission lands, and move the date.

## Where the project is

- **Latest release:** [0.12.8](https://github.com/yicheng47/runner/releases/tag/v0.12.8) on 2026-10-04: creating chats, terminals and missions from the keyboard ([#772](https://github.com/yicheng47/runner/issues/772)): ⌘↵ starts from anywhere in Start a chat and Start mission, Direct | Role switches with ⌘1/⌘2, and ⌘T and ⇧⌘M open a new terminal and a new mission. Enter in the model chooser opens the list or picks the highlighted model instead of submitting the form. Esc in pi shows Interrupted instead of Response failed ([#784](https://github.com/yicheng47/runner/issues/784)), Claude Code resumes a chat started through a symlinked directory such as `/tmp` ([#785](https://github.com/yicheng47/runner/issues/785)), Copilot resumes the conversation after `/clear` ([#786](https://github.com/yicheng47/runner/issues/786)), Codex captures conversations from a role's own `CODEX_HOME` ([#781](https://github.com/yicheng47/runner/issues/781), closed after a live check on 2026-10-04), and an inbox nudge for a message the slot has already read is skipped ([#766](https://github.com/yicheng47/runner/issues/766)). Behind those fixes, the runtime adapter refactor ([#777](https://github.com/yicheng47/runner/issues/777)) made each agent runtime one module behind a `RuntimeAdapter` trait, and the session state model ([#791](https://github.com/yicheng47/runner/issues/791)) routes every session status, draft and conversation-key update through one reducer, pinned by scripted replay scenarios across the five agent runtimes. 0.12.7 on 2026-10-02 fixed cancelled turns staying Working in Claude Code, Antigravity and Copilot.
- **Merged since that release:** Antigravity commands in missions and chats run in the session's working directory again instead of Runner's hooks folder ([#787](https://github.com/yicheng47/runner/issues/787), [#801](https://github.com/yicheng47/runner/pull/801)): the hooks folder is a workspace the model could pick, so Runner's existing start-of-turn hook now names the session directory as the default. The nightly feed builds from `main`.
- **In flight:** the 0.12 milestone has two open issues. Separating shell lifecycle from agent orchestration ([795](./features/795-shell-agent-boundary.md)) follows #791 and comes before the session host. A P1 bug that predates #791 surfaced again in its QA regression and is in a crew mission: pi delivers a crew message into an unsent draft ([#799](https://github.com/yicheng47/runner/issues/799)), because pi's empty prompt prefix leaves the draft detector unsure. Mission monitoring from a Runner chat ([748](./features/748-mission-watch-delivery.md)), a P1 spec under review, is in 0.13.
- **Next minor:** session host ([#645](https://github.com/yicheng47/runner/issues/645)) is the 0.13 headline and sole release blocker, moved forward from 0.14 on 2026-10-03. Missions as containers ([562](./features/562-mission-spawn.md)) and session-to-session prompts ([704](./features/704-session-send.md)) remain scheduled but do not gate 0.13.0.

## Decisions that shape the next releases

- **Runner is not an agent development environment.** Worktree isolation ([#403](https://github.com/yicheng47/runner/issues/403)) and the project tree with a read-only diff viewer ([#634](https://github.com/yicheng47/runner/issues/634)) were closed as not planned on 2026-09-22. Checkouts, file trees and diffs belong to git, the agents and the editor; Runner stays what sits between agents.
- **The README is the front door.** The landing page ([#468](https://github.com/yicheng47/runner/issues/468)) was closed as not planned the same day: visitors arrive on GitHub, and the README already explains roles, crews and missions in both languages.
- **Each agent runtime is one module.** Since #777 (2026-10-03), a runtime's argv, spawn hooks, status watcher, models, usage, skills and MCP entry live under `runtimes/<name>/` behind the `RuntimeAdapter` trait, registered in one `match`; the app's per-runtime icons and labels are one table in `runtime_ui.rs`. New runtimes ([#723](https://github.com/yicheng47/runner/issues/723)) and MCP clients ([#764](https://github.com/yicheng47/runner/issues/764)) start there.
- **Session state goes through one reducer.** Since #791 (2026-10-04), every status, draft and conversation-key update for a session passes through `SessionModel::apply` under `session/state/`; runtime watchers only translate their CLI's records into events. Status fixes change the reducer or a watcher's translation, and each is pinned by a scripted scenario and its compact golden under `session/fixtures/`.
- **OpenCode is no longer scheduled.** [#592](https://github.com/yicheng47/runner/issues/592) was closed as not planned on 2026-09-28; it is not shipped runtime support. New runtimes follow the [integration checklist](./arch/runtime-integration.md), with platform verification recorded separately from CI.
- **One `runner` binary, two modes.** Inside a mission the commands are unchanged and `--mission` defaults to the caller's own; outside, `--mission` is a flag. No second control binary, and no scoping by packaging: a mission agent's shell runs anything on `PATH`. A limit, if ever wanted, is an authorization check on the app side of `mcp.sock`.
- **A caller is the person at the app or a roster handle, never a location.** `human` on the bus means only the person at the app UI. Inside a mission the handle comes from `RUNNER_HANDLE`; outside, `--as <handle>` names a seat the caller holds, and no handle means the person at a terminal. An outside agent that drives a mission takes a seat first. The socket's post and signal tools carry a `from` handle validated against the roster. Seats without a Runner-spawned session are #562's.
- **Runner's MCP integration was removed for 0.11.0, the release that ships the CLI.** Two ways in at once would have been confusing. The `runner-mcp` bridge, the registrations Runner wrote, and the pinned row in Settings → MCP are gone; the socket stays as the CLI's implementation-detail transport, and Settings → MCP remains the catalog of the user's own servers.
- **#648 and #562 stay separate.** 648 is a surface over tools that exist and shipped in 0.11.0; 562 changes the mission model and is scheduled for 0.13. 648 reserves the coordinator verbs (`spawn`, `ps`, `wait`, `stop`, `done`); a `peek` at a worker's terminal is not supported, messages are the contract, and #562 owns the seats and the verbs.
- **pi MCP management is proposed, not shipped.** [#764](https://github.com/yicheng47/runner/issues/764) tracks adding pi to the user's MCP server catalog in 0.13. Runner currently writes no pi MCP entry and has no pi column in Settings → MCP; the Skills pane lists pi's two personal roots read-only. Mission coordination continues through the bundled `runner` CLI. The new spec's proposal to register Runner needs reconciling with the shipped MCP removal before implementation.
